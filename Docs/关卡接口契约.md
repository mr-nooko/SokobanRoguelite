# 关卡接口契约

## 数据与编辑边界

UGridLevelAsset 是可保存草稿，包含 RoomId、Size、Start、Goal、VoidCells、Walls、Rubble、Boxes、Enemies、StrengthLimit 和射线地形配置。UGridLevelAsset::ToLevel() 将其转换为 FLevel 值。编辑器面板直接编辑草稿资产，并通过事务记录资产变化。AGridScene::RefreshEditorPreview() 在编辑世界重绘当前草稿。GetLayoutWarnings() 返回布局问题字符串数组。布局检查结果为空表示该检查通过。

FLevelDraft 是规则层的内存草稿包装。Edit() 返回可写数据，Read() 返回只读数据，Warnings() 复用静态检查。它不会写磁盘。工作台资产的持久化由 UE 保存机制处理。

## 模拟与验收

FRules::Start(Level, Inventory) 创建会话。FRules::Apply(Session, Action) 更新会话并返回有序事件。FLevelGate::CheckLayout(Level) 检查棋盘每边 1～64 格、格子占用、唯一实体 ID、模块参数和射线配置。工作台、关卡缩略图和预览共用尺寸检查。

FLevelGate::Validate(Level, Resources, Limits, Solver) 先检查静态布局，再分别按 CapabilityBudget 与 ActualInventory 求解。未解锁的道具从两份预算中滤除。FValidation 包含聚合状态、静态问题、Capability 和 Actual 阶段报告。两个资源阶段按全局 MinimumSolutions 判定合法性，默认至少 1 解。显式难度分段再检查实际资源的目标区间。LegalityStatus 单独报告合法性，Status 报告两者组合。任一阶段明确不达标时返回 Fail。未能证明时可返回 Unknown。OpenFormal 使用过滤后的真实库存创建正式会话，验证不通过时返回空，可通过 OutValidation 读取失败和未确定的原因。工作台的「试玩关卡」是静态校验后的草稿入口，「正式准入模拟」使用与运行一致的验证策略。

ILevelSolver::Search(Level, Inventory, Limits) 返回 FSolutionReport。报告包含 Solvable、MeetsMinimum、Difficulty、CountLowerBound、bComplete、Witnesses。CountLowerBound 在未穷尽时是已发现的下界。项目准入保留最低解法门槛。生成分段显式选档时启用 `bRequireDifficultyBand`，真实库存按目标区间检查，困难发现第 4 解即超档，中等发现第 9 解即超档，简单找到第 9 解即可证明分档。困难和中等通过需确认上界。能力阶段只需达到全局最低解法数。`FValidation::TargetDifficultyStatus` 表示门槛达成情况，`FSolutionReport::Difficulty` 仍表示可证明的实际分档。未指定目标时，正式准入达到全局最低解法数即停。工作台继续搜索以提供难度报告。Witnesses 是可回放的成功动作序列，现有深度优先实现未承诺最短路径。

## 生成扩展点

ILevelGenerator::Generate(Request) 是扩展接口。FGenerationRequest 字段为 Seed、Complexity、MaxAttempts、Resources、Search。FGenerationResult 字段为 Status、可选 Level、Validation、Attempts、bFallback。生成器实现应只返回经过验证的可交付关卡，并将预算不足保留为 Unknown。`FTemplateLevelGenerator` 已实现内置和手工模板、逐次简化与后备重验，`Trace` 记录每次候选。可独立运行 `SokobanGenerate` 导出 JSON。随机候选和手工资产共用同一 FLevel 验证入口，命令参数见《关卡生成器设计》。


VoidCells 为空时有效区为完整矩形。FRules::IsInBounds 检查外框，FRules::IsInside 进一步排除挖空格。布局、模拟、求解和 3D 预览共用这一区分。

## 结构工具与音效

`UGridStructureAsset` 属于编辑器模块，以选区外接矩形的左上角为坐标原点，只记录实际选中的墙、碎墙、挖空、箱子和敌人。多块选区之间未选中的格子在摆放时留空，保留目标格的原状。箱子和敌人保留方向与模块参数，摆放时重新分配实体编号。结构不保存起终点、房间参数、美术配置或普通空地。记录选区须同时包含尖刺箱的箱体和尖刺。摆放前检查完整范围及物件占用，通过后一次写入关卡草稿，最终仍使用原有的关卡合法性与可解性验证。

`UGridVisualProfile::Sounds` 按表现事件绑定音频资产。运行时由 `AGridScene` 消费规则事件和终局表现，规则层及生成器入口保持原数据格式。

## 配置职责与接入顺序

### 已统一的入口

- **关卡准入与库存。** 「项目设置 → 游戏 → 推箱子关卡」维护开局库存、道具解锁、能力验证库存、动作步数、节点预算和目标门槛。两阶段分别使用配置的能力库存和实际库存，工作台库存输入默认跟随项目开局值，可改成切关时的实际余量。正式流程仍由玩家确认切关，准入通过后才提交状态。接入生成器时，通过 `UGridProjectSettings::MakeResourceContext` 和 `SearchLimits` 填充 `FGenerationRequest`。
- **组件编号与检查。** 画笔和结构工具共用 `UGridLevelAsset::AllocateEntityId`，箱子和敌人使用同一个关卡内命名空间。移动保留编号，新建和复制分配可用编号。关闭箱子的爆炸开关会清理两个随附选项；已有草稿可选中箱子使用「清除残留爆炸选项」。工作台从草稿属性面板收到变更后会重绘棋盘、刷新组件列表和布局警告，并清除过期的准入报告。
- **项目主题与覆盖。** 项目设置引用默认 `UGridVisualProfile`。关卡美术配置中的偏移和缩放分别选择「自动」「继承」或「覆盖」。自动模式沿用旧资产中非默认的值，零偏移和单位缩放会继承；如果这两个值本身就是关卡需要的设定，请显式选「覆盖」。默认主题自身的偏移和缩放直接生效。
- **组合箱表现。** 工作台、关卡缩略图和 3D 使用同一外观分类，主外观按爆炸、尖刺、弹射、普通的优先级选择。工作台在名称中标出并存的模块，尖刺占格继续单独显示。

### 各环节可编辑的入口

- **技术策划和关卡策划。** 在 `UGridCampaignSequence` 填写总关数与手工关位置，空位共用生成与后备配置。开局用 `BuildSlots` 拒绝重复、越界或缺资产的手工位，再展开固定长度的槽位数组。已保存的旧版逐关配置在总关数为零时可按原方式运行。实际进入生成槽位时使用本轮真实库存，以槽位位置派生子种子。
- **关卡编辑和组件扩展。** 把可摆放对象做成组件预设，保存默认模块组合、展示名称与推荐方向。画笔、右侧属性、组件列表和浏览器读取同一组件描述。编辑命令集中处理占位、编号、删除、批量事务和冲突预览。规则层仍集中定义行为类型、棋盘状态变化和结算顺序。
- **美术和音效。** 项目设置和单关覆盖已可使用，后续序列资产可增加一层主题覆盖。网格、材质、交错地板、位移、缩放、音效和附件都通过配置项维护。工作台显示实际解析到的资产与来源，支持定位、替换与同图预览。资产迁移前检查烘焙收录，旧配置增加新字段时保留原引用。
- **生成、试玩和 QA。** 生成器只提交规则数据和报告，其配置包含模板、目标难度、复杂度、种子、搜索与重试预算。正式进房共用准入入口，回车后重验下一关并只在通过后提交。保存或交付生成结果时附上种子、实际库存、验证结果、规则版本和代表解法。工作台可读取报告并回放，QA 可用同一输入复现。较大的求解任务使用规则数据快照，避免在界面线程长时间运行。

### 迭代顺序

1. 实体编号、爆炸组合属性与共用验收口径已实施。非法草稿可保存，正式入口按实际资源复验。
2. 迁移教学房与关卡序列，补上逐项显示有效美术资源与复用组件预设的编辑入口。策划可以重排关卡和更改提示，美术可以替换模型材质，纯内容变更无须重新编译 C++。发布包仍须包含更新后的资产。
3. 混合序列已接入生成器。状态索引和资源更新只在下一槽位验证通过后提交。独立命令提供生成轨迹和解法供 QA 验证。

当前版本回归在 UE Session Frontend → Automation 中运行 `Sokoban`。V0.7 Python 测试包用于复现旧规则，包含旧版的弹射方向序列，当前 UE 的直线滑行由 `Sokoban.Rules.StraightEjectUntilBlocked` 验证。

## 正式准入与运行时草稿

- 开始一轮和手动确认切关时，控制器将关卡、库存和求解设置按值传入后台任务。界面显示准备状态并阻止重复提交。结果通过后，控制器在游戏线程进入关卡。
- `UGridLevelAsset::PlaytestHint` 的显示名为「关卡文字说明」，原字段保留以兼容旧资产。手工序列条目的非空提示优先。生成关的提示和 `FGridRoomReward` 由序列默认值与分段设置解析，生成结果和后备结果使用同一套槽位配置。
- 通关后的赠药由控制器每关结算一次，HUD 只显示实际入账的种类和数量。通过回车变更关卡时，准入使用含奖励的库存快照。验证失败留在当前通关状态，重试沿用已有库存。死亡由规则层清空库存和倒放历史，胜利优先规则仍适用。
- 指定难度门槛时，实际背包找到的独立解法可用能力库存逐条重放。能力库存重放达到全局最低解法数后即满足能力阶段门槛。证据不足时仍执行能力阶段搜索。
- 运行时编辑按当前背包在后台验证。保存通过后交替写入主草稿槽与备份槽，写入后重新读取校验。载入选择最新可读版本，旧版单槽存档可继续读取。
- 可复用结构在记录及放置前校验结构内占格，箱体与尖刺分别占格。配置了连推及箱子模块的关卡会显示提示。多箱连推只移动箱体一格，保持尖刺的碰撞占格。尖刺扫击、弹射、主动爆炸由玩家直接推单箱触发。爆炸箱之间按八邻域连锁，整波同播，播完才允许下一步。

爆炸的斜向传播以爆炸中心的两个相邻正交格为准。挖空与普通墙一样算阻挡。两侧均阻挡时，斜角上的有效地块不受本次传播影响。敌人伤害和爆炸箱连锁共用此判定。
