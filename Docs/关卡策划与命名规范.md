# 关卡策划规范

适用范围为推箱子战斗 Roguelite 关卡工作台第一版。玩法规则以 Game Rule Spec V0.7 及已确认的 Q41–Q47 为准。本文规定关卡身份、草稿编辑和验收口径。

## 命名与路径

- 规则 ID 使用大写 ASCII 与下划线，格式为 GRID_至少三位十进制序号，例如 GRID_001。ID 在关卡库中应唯一，保存后作为稳定标识。资产改名时保留 RoomId。
- 新建草稿由工具分配 ID 和 /Game/Maps/Drafts/DA_Grid_001 形式的资产路径。工具检查该目录同名包和内存中已加载的同名包。正式入库时还应检查全库 RoomId 唯一性。目前由维护者检查。
- 自建地图使用 L_Grid_<主题>_<三位序号>，例如 L_Grid_Laser_001。主题用英文 ASCII，地图可作为多个草稿的预览容器。地图名与 RoomId 独立。
- 面板放置的箱子使用 B_XX_YY，敌人使用 E_XX_YY。坐标为创建时的 X、Y，两位十进制。实体 ID 在单关内必须唯一。手工改数据时要避免同 ID。
- 现有 GridWorkbench 和 DA_Workbench 是开发样例，保留原路径和引用。新草稿使用上述命名。
- 可读关卡标题放在设计记录。RoomId、资产名和文件名不使用本地化标题。

## 格子约定

坐标从左上角的 (0,0) 开始，向右为 X 正方向，向下为 Y 正方向。面板支持 1～64 格每边。起点和终点各有一个必填坐标。重设起点或终点时，旧位置变为普通格。擦除用于墙、碎墙、箱子和敌人。尖刺与射线初始朝右，每次旋转顺时针 90°。尖刺占独立碰撞格，应检查箭头前方的格子。

## 关卡引导与药丸经济

手工关的文字说明随关卡资产保存，序列可以为同一资产提供不同场合的提示。生成关按序列或分段配置说明。提示在玩家操作时显示，可用于说明当前组件或教学目标，为完成目标而赠送的药丸在通关后才显示。

每关可配置赠送两种药丸的各自数量，默认为 0。通关后发放一次，有实收才显示名称与数量。玩家按回车确认下一关，系统以本关实际剩余药丸加新增赠药作为准入库存。遇到校验失败时保留通关结果和背包供重试。死亡立即结束本轮，背包和倒放记录清空，新一轮从项目配置的开局库存开始。

## 爆炸箱原地引爆

直接推动一个爆炸箱时，若它正前方紧贴敌人、碎墙或另一箱的尖刺端，爆炸箱在原格引爆并按八邻域规则结算，玩家留在原位。接触型和射线型敌人都适用。此次消耗一步，作为有效动作纳入求解。普通墙、箱体、终点、挖空和地图边界不触发这次原地引爆，大力士推动多个箱子时仍按整链规则处理。本次爆炸不会因碎墙消失而继续向墙后传播。

## 草稿与正式验收

草稿允许保存并显示布局问题。当前工作台的 Play 入口检查布局并用固定试玩背包启动。正式入口由 FLevelGate 校验布局、能力阶段和真实背包阶段，能力和实际库存阶段均须证明达到全局最低解法数，默认 1 解。显式生成难度独立验收，困难 1～3 解、中等 4～8 解、简单至少 9 解。搜索预算不足时，未证实的结论保持 Unknown。工作台即时显示布局结果。「验证关卡」会按指定背包生成双阶段报告。解法回放属于后续功能。



## 弹射箱

玩家成功单独推箱一格后，弹射箱沿推动方向继续逐格滑行，遇到墙、碎墙、箱子、敌人、终点或地图边界等阻挡就停在前一格。玩家只走最初的一格。每一格都按既有尖刺扫击与射线规则处理。撞到别的箱子时停止，受到碰撞的箱子不会启动自己的模块。

多箱连推只平移箱体一格，尖刺继续占格。玩家直接推单个特殊箱时才启动模块。弹射箱停稳后结算自身启用的爆炸。如果初次推动成功，但弹射起步受阻，由「弹射起步受阻时爆炸」决定是否引爆。已引爆的爆炸箱仍按八邻域连锁。旧资产中的非空弹射方向序列和正数定距滑行均迁移为沿推动方向弹射。

八邻域爆炸向斜角传播时，检查斜线上相邻的两个正交格。挖空与普通墙同样阻挡。只有两侧都阻挡时才保护斜角另一侧的有效地块。因此一墙一挖空、两侧都挖空均挡住爆炸。只有一侧挖空且另一侧是空地时，爆炸仍可到达。伤害和连锁引爆都使用同一规则。

草稿创建时可自定义资产名称，序列选择器显示这个名称。关卡编号仍由工具单独分配。删除前由浏览器报告序列引用，优先替换后再删，也可确认强制删除。
