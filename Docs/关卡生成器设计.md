# 关卡生成器设计

目标是产出可以用当前真实背包通关的房间。输入包含随机种子、目标复杂度、能力解锁、能力阶段的假设预算、真实库存和搜索限制。生成器与手工编辑器都提交 FLevel，正式运行前经 FLevelGate 验证。地图布局策略与验证器可以分别替换。

1. 从少量可人工审查的结构开始。首批结构覆盖射线与可移动掩体、尖刺攻击绕路、爆炸与碎石。每个结构保留用于随机化的起点、出口、模块位置和可选支路。可用模块由解锁和配置决定，候选图允许用实际剩余道具。
2. 由请求种子为每次尝试推导子种子，选择结构、朝向和支路，再布置箱子及敌人。保持稳定的候选遍历顺序，记录种子与尝试编号，确保可回放。
3. 对候选执行布局检查，再用同一 FRules 驱动两个资源阶段的有界求解。按有效动作序列计数，保留绕路、排除无效动作，勿用全局已访问状态抹掉不同的动作历史。能力阶段达到全局最少解法数即停，默认 1 解。显式目标按区间验收，困难 1～3 解、中等 4～8 解、简单至少 9 解。区间已可确定时提前结束，预算耗尽且区间或主机关证据未确认时保留 Unknown。
4. 若验证拒绝或结果不足以入选，则记录拒绝原因，逐步降复杂度。优先减少组合模块或弱化支路约束，保留可达到全局最低解法数的路线空间。达到尝试上限后，按当前规则、库存与预算重新验证后备图。后备同样无法证实时返回失败或 Unknown，由上层决定是否扩大预算或结束本次请求。
5. 每份结果记录主种子、子种子、复杂度、搜索预算、能力与实际库存、代表性解法及候选来源。编辑器提供同一数据的草稿编辑与验证入口，并能用代表性序列回放。

## 独立生成命令

UE 编辑器目标编译后可运行以下命令。示例验证零库存的射线掩体布局，并把关卡和动作序列写入 JSON。

```powershell
& 'E:/UE5/UE_5.5/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' 'E:/kltest/SokobanRoguelite/SokobanRoguelite.uproject' -run=SokobanGenerate -unattended -nullrhi -nopause -nosound -ddc=NoZenLocalFallback -Seed=42 -Complexity=2 -Template=BeamCover -Difficulty=High -Strength=0 -Undo=0 '-Output=E:/kltest/work/GeneratedBeam42.json'
```

- `Seed` 固定候选顺序、朝向和局部布置。`Complexity` 为 0～3，尝试失败后逐次降低。内置布局分别覆盖 0 绕行、1 爆炸碎墙与弹射通道、2 尖刺扫击与射线掩体、3 连续破障、弹射与爆炸组合及大力士推链。自动选择时会跳过当前库存无法使用的大力士推链模板，最近使用过的结构在有其他候选时后选。`Template` 可固定为 `Detour`、`BlastRubble`、`SpikeSweep`、`BeamCover` 或 `StrengthChain`。指定模板类型后按复杂度择其最接近的结构。内置候选每个复杂度先尝试两次，再降一级。
- `Difficulty` 设定精确难度分档。省略时继承项目准入的最低解法门槛。`Strength` 和 `Undo` 表示本次实际库存。省略时采用项目配置的开局库存，解锁和能力库存继续读取项目设置。`MaxActions` 和 `NodeBudget` 可覆盖项目预算。
- `Attempts` 默认 8，范围 0～64。尝试用完后独立验证自定义后备关，或按顺序验证内置后备候选。`NoFallback` 可关闭后备，适合单模板调试。命令退出码 0 为通过，1 为本次候选均明确未通过，2 为未确认，3 为参数或输出错误。
- 报告包含尝试子种子、模板、尝试复杂度 `attemptComplexity`、内置模板实际复杂度 `templateComplexity`、请求库存、解锁状态、两阶段解法下界和布局错误。通过时提供关卡数据和真实资源阶段的可回放序列。达到目标后可提前停止，此时 `solutionCountComplete` 为假。
- C++ 调用 `FTemplateLevelGenerator::Generate`。可用 `AllowedTemplates` 约束内置模块，或传入 `AuthoredTemplates` 作为候选来源。`FallbackLevel` 可替换后备关。接入工作台时可用 `UGridLevelAsset::SetFromLevel` 写入独立草稿。

## 内置候选的设计检查

绕行关用转角、并行路线或庭院组织动线。机关关把起点、操作位和出口通过墙或挖空分隔。部分工房按种子开合整组边室，主通道和关门位置由模板定义。

内置机关候选通过两阶段验收后，还要检查初始箱子、敌人、射线和地形保持原位时，玩家能否直接步行到终点。存在纯走路捷径的候选会被拒绝。生成器还会以实际背包回放见证解法，至少一条解法需要展示模板对应的机关行为，例如推开射线掩体、尖刺击杀、多格弹射、爆破碎墙或同次推走两箱。这项检查保留原有的有效动作序列计数规则。

报告的 `designIssue` 给出设计拒绝原因。内置候选在同一轮尝试中优先换用还未试过的结构，并优先避开本局近期用过的模板。手工传入的模板及自定义后备沿用原有规则验证。

## 开发前边界审查

### 以哪个入口为准

- 编辑器保存的是可继续修改的草稿。静态合法性来自 `FLevelGate::CheckLayout`，包括箱体与尖刺分别占格、唯一实体编号、方向、地图挖空和模块参数。布局通过后，正式验收调用 `FLevelGate::Validate`，能力预算和真实库存各自达到全局最低解法数才通过。试玩入口只做静态校验。编辑器验证和生成器共用项目设置。对比结果时使用同一组解锁、库存和搜索预算。
- 生成器直接产出 `FLevel`，复用 `FRules::Start/Apply`，不依赖场景碰撞、编辑器事务、美术或音效。工作台的结构资产是编辑器专用局部布局，胜利条件、起终点和房间参数都需由候选构造器提供。首版用规则模块内的固定结构模板，编辑器结构资产转换留到集成。
- 规则层、工作台和试玩均支持每边 1–64 格。内置模板的起终点分别布置在不同格子。当前同格会直接胜利，只产生空序列，只能满足要求不超过一个解的门槛。射线模板显式配置地形遮挡。挖空会截断射线，即便配置为穿过墙和碎墙。旋转或镜像时同时变换棋盘尺寸、挖空、起终点、物件位置、尖刺和射线方向。弹射方向由玩家实际推动方向决定。

### 生成前需补齐的回归

1. **大力士与模块组合。** 当前 UE 先检查多箱链的上限与占格。玩家直接推单箱才会触发尖刺攻击、弹射和主动爆炸。连推只做箱体平移，尖刺仍参与碰撞。已引爆的爆炸箱照常传播八邻域连锁。
2. **查清射线的可观察结算点。** UE 对单箱直线弹射逐格更新，首次暴露后会继续结算爆炸并保留死亡。大力士链当前是在整链位移和玩家位移后刷新射线。接入大力士与射线混合模板前，补一个短暂失去遮挡又恢复的用例，明确整链位移是否作为一次原子结算。通关与射线暴露发生在同一动作时另测终点胜利优先。
3. **验证证据需要能复放。** 求解器支持 1–10 步倒放，试玩按 Z 可选当前关卡的倒放步数。独立生成阶段用 `FRules::Apply` 回放验收序列，检查库存和终局，测试多步倒放只扣一次且不能跨房间。集成阶段用试玩界面补做人工验收。首版无道具模板可在两阶段的真实求解之外增加零道具回归。
4. **固定对外的计数口径。** 现有求解器按有效步限制搜索，大力士启用命令与随后移动合并占一步，回放中仍保留两条命令。有效倒放也计一步，消耗大力士后走同一路与普通走法是不同序列。当前深搜优先级会影响有限预算下找到的下界。保留同终态的不同序列，拒绝只计步或扣道具的失败推动，显式高难和中难需要确认解法上界。选择继承项目准入时，按项目设置的最低解法数验收。机关模板同时需要一条展示主机关的真实库存通关见证。

### 独立生成器首版验收

- **输入与输出。** 现有接口足以实现基础候选生成和两阶段验收。`Complexity` 控制模板布局与模块组合，难度来自真实资源阶段的求解报告。作为开发默认，用少量可审查的小型模板覆盖可移动掩体、单箱尖刺侧扫、单箱爆炸清碎墙。正式约束继续用实际请求的资源与预算。
- **尝试与后备。** 子种子及候选遍历顺序固定。同一请求与同一模板版本应生成同一候选并记录其来源。分开发现布局错误、明确未达最低解法数、预算不足三类原因。按既定顺序降复杂度和试后备，后备必须用当前请求重新验证。只有 Pass 才返回可交付关卡。若有候选因预算不足仍无法判定，耗尽尝试时保留 Unknown。尝试失败仅表示本次候选未通过。
- **测试切入点。** 第一批独立用例覆盖固定种子复现、非法候选拒绝、能力通过但真实库存不足、代表解法逐条复放、困难和中等达到超档阈值时停止，简单达到最低解法数时停止、降复杂度与后备重验。通过 `FGenerationResult::Trace` 读取子种子、候选来源和每次校验结果。

## 手工关与生成关的混合序列

### 现有基础

`UGridLevelAsset::ToLevel()` 已能把手工草稿转换为 `FLevel`，`ILevelGenerator` 也约定返回 `FLevel`。两类房间可以共用规则、求解和 3D 棋盘。现在 `AGridPlayerController::NextRoom()` 只在演示关通关后通过回车切到下一关。草稿试玩结束后停在当前房间。当前试玩支持可配置的手工关卡序列和进房校验。正式混合序列通过 `UGridCampaignSequence` 配置。项目默认资产为 `/Game/Maps/Campaign/DA_DefaultCampaign`。输入总关数及手工关的 1 起始位置，空位按共享生成设置自动补齐。

### 序列如何配置

新增一个正式关卡序列数据资产，按序保存关卡条目。每个条目有稳定的编号、显示名称、来源类型和适用的验收参数。来源类型决定房间数据从何处取得。

- **手工条目**引用指定的 `UGridLevelAsset`，载入后读出 `FLevel` 及该房间的美术配置。只有显式加入序列的手工资产才作为正式候选。
- **生成条目**保存模板范围、复杂度、目标难度、尝试上限和搜索预算。`ILevelGenerator` 使用本次序列的种子、该条目的稳定编号和进房时的实际资源生成房间。生成结果在本局内使用。需要人工修订时，可把结果另存为草稿，再以手工条目引用。
- **后备房间**可以引用人工验证过的资产。它在当前条目内替代生成候选，仍占同一个序号，并用本次的真实库存以及当前条目的验收条件重新验证。
- 美术配置可以由条目覆盖，未覆盖时采用手工关卡资产的配置或序列默认配置。棋盘、规则与音效入口共用。

配置示例为「01 手工射线教学 → 02 生成练习 → 03 手工尖刺关 → 04 生成综合关 → 05 手工终章」。正式推进按条目顺序。关卡库中的资产名称、文件夹和生成尝试次数都独立于这一顺序。序列也支持开头是生成关，或只有任意一种来源。

### 共用进房流程

正式运行由当前轮次的槽位数组、主种子、当前条目索引和会话库存共同确定。开局复制序列槽位，进入生成槽位时从主种子和位置导出种子，并读取最新的正式库存。控制器处理按键和进房提交，`AGridScene` 负责表现。求解器和布局生成器接收规则数据。

1. 根据下一个条目解析手工资产或请求生成器。开局使用配置的起始库存，后续使用上一关正式结算后的剩余库存。
2. 两类候选共用静态合法性与两阶段验收，能力和真实库存阶段都应用全局最少解法数，默认 1 解。困难和中等须确认上界，简单找到 9 解即可证明分档。继承项目准入的生成关按最低门槛验收。候选验证和启动会话必须使用同一份有效库存。生成器已经提供与本次布局、库存、规则和搜索上限匹配的可信验证结果时，进房可复用结果。首版也可先通过现有 `FLevelGate::OpenFormal` 统一接入。
3. 验收通过后，新建 `FSession`，从新房起点开始，回合置零、清空当前关内倒放历史和待生效的大力士状态，只携带上一关剩余道具。复用当前 UE 地图与 `AGridScene`，清理上房通关表现，应用新房的美术配置，再一次性提交新棋盘和序列序号。
4. 手工教学关建议验收零道具背包，保证前一关耗尽道具也可进房。生成关允许针对真实库存出题。搜索预算耗尽且未达标记为 `Unknown`。候选失败可以继续尝试或换经验证的后备图。若后备仍无法通过，保留通关画面和当前序号，显示下一关未能准备完成，并提供重试。失败保持为加载问题，死亡、通关整局保持各自的结果。

### 通关后手动切换

通关后先播完最后一格移动和终点粒子，再由玩家按回车请求下一关。系统用上一关结算后的剩余道具，读取并验收序列下一项。校验失败保留当前序号、通关状态和道具，显示原因。校验通过才提交新房、重置回合并清空倒放历史。最后一关停在整局通关画面。独立草稿试玩停在本关结算。

当前可在关卡预览对象上填写「试玩关卡序列」，按数组顺序引用手工草稿。单关「关卡草稿」有优先级，留空该字段时才运行已填序列。两个字段都为空时使用六关教学。未来生成条目接入时也沿用回车请求和先验证后提交的流程。

### 集成验收顺序

先用两张手工关验证手动切换与库存结转，再插入可控的生成结果验证「手工 → 生成 → 手工」，最后接入实际生成搜索和后备流程。覆盖以下边界。

- 动作结算先于截取库存。使用大力士推进后，生成器收到扣除后的真实库存。
- 当前关通关赠药先结算入背包，再由回车触发下一关生成或校验。奖励由序列的空位默认设置及分段覆盖提供，使用后备关时仍沿用该槽位配置。当前关尚未获得的奖励不会参与当前关自身的可解性验证。
- 演出期间回车不推进，演出结束后主动按回车才发起请求。最终条目结束时无需请求下一房。
- 新房正确刷新尺寸、布局和美术，倒放无法恢复旧房。若上一房按住移动键，新房落地后先等待松键。
- 生成返回 `Unknown` 或手工资产加载失败时保留当前房间。重试成功后只提交一回。重开后迟到的旧结果丢弃。
- 同一序列、相同种子、相同实际资源与配置可复现候选。改变房间资源后重新验收。

先安排手工关，再给空位配置生成分段。分段不得跨过手工关、彼此重叠或超出总关数。更改序列时，冲突输入会被恢复，错误显示在「配置检查」。
